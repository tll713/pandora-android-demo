# 潘多拉智能掌上工作系统

每日事项默认自动错开配色，新建时优先选用当天未使用的颜色，也可通过“颜色”按钮手动修改；配色同步到事项月历和公司日历。首页已移除“00/06”计数、事项月份标题的小箭头和新增事项下方的配色选项，新建事项自动配色。写日志时自动列出所选日期的事项，可一键带入正文，保留已有填写内容。日志页只显示本人日志，关键词输入即筛选，可组合日期范围，中文输入过程中保留输入框与焦点。所有日期入口统一使用可输入或下拉选择的年份、月份下拉和日历选日，移除顶部完整日期输入栏。年份可直接输入1000–9999年，也可点击同一控件右侧箭头选择；下拉以所选年份为基准，显示前6年、当年和后5年，共12年（例如2026年显示2020–2031年），输入或选择后范围随新年份更新，接近边界时平移范围保证12项。未输入完整有效年份时提示并禁止确认，输入期间保留焦点与光标。切换年月时自动校正月底与闰年日期，继续遵守事项、日志的日期范围限制，保留“今天”和时间分钟选择；详情弹窗底部统一留白。

公司新增“通讯录”，按部门、岗位展开成员，支持搜索姓名、部门、岗位和手机号；成员任务清单支持关键词、状态和优先级筛选，筛选条件与本人任务列表独立。任务清单、任务月视图中的详情均沿用原有任务权限，可申请编辑、删除，负责人可记录进展和完成任务；变更仍需审核。任务月视图通过带“选择日期”提示的年月标题跳转，移除换月箭头；“回到今天”显示当天日期并提供悬停说明。通讯录日志复用原有详情与评论功能：管理员、创始人可查看和评论他人日志，部门负责人限本部门，团队长限本部门员工，员工仅可看本人日志；任何人都不能自评，本人最近三天日志可编辑。联系人接口只提供基本联系信息，不返回身份证号。公司任务列表只显示本人负责的任务（含共同负责），整行支持点击和键盘打开。任务起止时间、事项改期及日志日期筛选使用统一日期选择器，可直接切换年月、使用快捷日期并精确选择分钟。

公司日历的月、周视图均在左上角显示“选择日期”入口，点击可选年月或直接跳转日期。周视图显示当前周的日期范围，可用两侧箭头切换上一周、下一周。

任务创建、编辑和删除申请均可选择单个或多个审核人，按横向级联菜单选择：左侧部门 → 中间职位 → 右侧人员，点击部门或职位右侧的箭头进入下一级；审核菜单和通讯录均将管理中心置顶，职位按创始人、系统管理员、部门负责人、团队长、员工由高到低排列；输入姓名、职务或部门实时筛选，筛选切换保留已选人员。审核人可选任意启用成员，包括普通员工和其他部门成员，且不能选择本人。被指定的成员可在首页消息的“待我审核”中查看和处理该申请，完成后仍可查看本次申请及审核结果。多人会签无先后顺序，所有选定审核人通过才生效，任意一人驳回即结束；每人只能提交一次意见，申请详情显示逐人状态、备注与通过人数。未指定人员不能审核。已有待审申请及未传审核人字段的旧客户端继续按原独立审核规则处理。

此更新需重启后端并刷新 App 页面。后端启动会自动补充事项颜色和审核人、审核记录字段，保留原有业务数据；Android APK 需重新构建以包含更新后的前端资源。

面向中小企业的任务协作与工作日志系统。按甲方诉求实现「全员 App 端 + 管理员 Web 端 + 统一后端」的全栈架构：员工在 App 上处理任务、记录进展、写每日日志；管理员在 Web 端维护组织账号、查看系统日志和管理十大内容，任务申请在 App 任务页提交，审核在首页消息中处理。

首页消息包含申请审核、事件纪与任务看板更新。管理员和创始人可以在“审核结果”查看可见申请的处理结果；普通成员查看本人提交或本人被指定审核的申请结果。首页内容发布、修改、撤下，以及任务创建生效、修改、进展、完成、删除会生成持久通知，只向相应查看范围内的成员发送。工作区在页面恢复可见时刷新，并每 30 秒同步一次；消息列表展示最近 200 条内容更新通知。

新建或编辑任务时，管理员和创始人可在标签选择区新建、编辑共享标签；其他角色只能选择标签。打开任务表单时会重新获取标签，已打开的表单也会同步更新，保存标签时保留任务草稿。日志按部门、职位、成员、日期及提交情况筛选，成员列表随部门和职位联动；每日日志记录全天工作，不再提供标签或关联任务的填写与筛选。

本次更新后需重启后端并刷新 App 页面。后端启动时自动创建 `workspace_notifications` 表并保留现有数据，更新通知从本次版本启用后的变更开始记录。

## 系统架构

```
┌──────────────┐   ┌──────────────┐
│   App 端      │   │  Web 管理端   │
│ (安卓 WebView │   │  (原生 JS，   │
│  /浏览器预览)  │   │  由后端托管)  │
└──────┬───────┘   └──────┬───────┘
       │   HTTPS + JWT     │
       └────────┬─────────┘
        ┌───────▼────────┐
        │  Spring Boot    │
        │  后端 (8080)    │
        └───────┬────────┘
        ┌───────▼────────┐
        │   MySQL (pandora)│
        └────────────────┘
```

- `server/`：后端服务。Java 21、Spring Boot 3.3、Spring Security + JWT 登录鉴权、Spring Data JPA、MySQL 8。
- `web-admin/`：Web 管理端，原生 HTML/CSS/JS，由 Spring Boot 静态托管，与后端同端口（8080）。
- `pandora-app/`：App 端，原生 HTML/CSS/JS 页面 + 安卓 WebView 外壳；也可直接在浏览器预览调试。

## 核心功能

- 任务支持多个负责人，截止时间精确到分钟。
- 任务详情记录文字进展（不做百分比进度），任务完成无需审核。
- 任务的创建、编辑、删除需提交申请，由具备审核权限的角色审核通过后生效；不能审核自己的申请，驳回必须填写原因。
- 每人每天一篇综合工作日志，可补写或编辑最近三天；每次修改保留旧版本，更早日志只读。
- 月、周、日视图按月／周／日组织日志与关联任务，可直接选日期；公司任务表格仅显示本人负责的任务，支持关键词、状态和优先级筛选。
- 普通成员可申请创建本人任务，管理角色可分派管理范围内的负责人；编辑、删除权限由服务端校验。
- 使用手机号或姓名登录，管理员建号自动生成 18 位随机强密码，创建后仅展示一次。
- 个人资料可查看性别、身份证号、手机号；“我的”页可更换头像。
- 每日事项按天记录，仅本人可见，可在首页勾选完成。
- Web 管理端提供组织与账号、系统日志、十大内容三个栏目；App 保留任务标签，采用浅色背景与深色文字，没有选标签的任务按「长期任务」显示。系统日志汇总登录、写日志、评价日志、任务进展与审核、每日事项、账号操作等全部流水；十大内容按 01—10 位置与 App 首页「事件纪」一一对应。

## 本地运行

本地演示模式首次升级时，为内置账号一次性初始化近 30 天的普通工作日志，按账号和日期保留部分未提交状态。旧演示日志转为普通已提交记录并去掉标题末尾的“（演示）”，所选未提交日期仅清理未修改、无评论的演示记录；本人提交、版本和评论保留。日志保存到数据库后参与提交统计，后续日期由成员本人填写，重启或定时任务不会自动代填。上述内容属于本地初始化数据，不表示员工本人曾执行提交操作，普通新建账号也不会自动生成日志。

每日事项在启动时及每天北京时间 00:05 为内置账号补齐近 7 天和本月剩余日期（月末至少覆盖未来 3 天），每个尚未初始化的日期补足至 6 项，保留已有事项和完成状态；初始化后删除的事项不会重新生成。`PANDORA_DEMO_DATA_ENABLED=false` 关闭内置账号初始化及定时补充，正式环境默认关闭。

此次更新需重启后端完成日志转换，再刷新 App 和 Web 管理端。手机首页已移除公司公告；组织账号输入关键词即时筛选。App 日志页仅显示本人日志，其他成员日志通过公司通讯录按原有权限查看与评论。

环境要求：JDK 21、Node.js 20+、MySQL 8（本地 root 密码见团队内部记录）。Windows PowerShell 下 npm 命令请使用 `npm.cmd`。

### 一键启动（Windows）

首次按下方说明准备好数据库，之后只需：

1. 启动本机 MySQL 服务，确认已经准备好下方的 `pandora` 数据库及对应账号。
2. 双击项目根目录的 `start.cmd`。首次启动后端时，按提示输入实际 MySQL 用户名和密码；脚本自动生成随机 JWT 密钥，将配置保存到 Git 忽略的根目录 `.env`，以后无需重复填写。也可手动复制 `.env.example` 为 `.env` 并填写。
3. 等待提示“启动完成”。
4. 打开 App 浏览器预览 `http://127.0.0.1:5173`，或 Web 管理端 `http://127.0.0.1:8080`。
5. 使用完毕后双击 `stop.cmd`。

启动窗口可以关闭，服务在后台继续运行。重复启动时会复用已经运行的潘多拉服务，无需重新填写配置；若端口被其他程序占用，会给出提示。后端代码更新后，先双击 `stop.cmd`，再双击 `start.cmd`，使新代码生效；只刷新浏览器不会更新后端进程。停止脚本仅结束由本项目启动脚本启动的进程，记录文件丢失时按当前脚本的完整路径恢复识别，不会停止 MySQL 或单独运行的其他服务。

前后端日志位于 `tmp/run/`，每次启动生成单独的 `.log` 和 `.error.log`。数据库账号或连接出错时查看 Backend 日志。首次启动需要联网下载 Maven 依赖，脚本优先使用已安装或已缓存的 Maven；等待超过 3 分钟会停止本次新启动的服务并提示重试。

仅检查环境而不启动服务，可在根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\workspace.ps1 -Check
```

手机 APK 连接后端同样需要运行 `start.cmd`，手机与电脑连接同一网络；电脑 Wi-Fi IP 若变化，需更新 APK 中的服务器地址。脚本不会修改数据库账号、系统服务或防火墙设置。

### 1. 准备数据库

用 root 登录 MySQL 执行：

```sql
CREATE DATABASE pandora DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'pandora_app'@'localhost' IDENTIFIED BY '请替换为独立随机数据库密码';
GRANT ALL PRIVILEGES ON pandora.* TO 'pandora_app'@'localhost';
FLUSH PRIVILEGES;
```

将上面设置的实际密码填写到 `.env` 的 `PANDORA_DB_PASSWORD`。表结构由后端按 `server/src/main/resources/schema.sql` 创建；只有演示配置会写入演示数据。

### 2. 启动后端（端口 8080）

```powershell
# 手动启动不会自动读取根目录 .env，需先在当前终端设置环境变量
$env:SPRING_PROFILES_ACTIVE='demo'
$env:PANDORA_DB_PASSWORD='填写实际数据库密码'
$env:PANDORA_JWT_SECRET='填写至少32字节的随机密钥'
cd server
.\mvnw.cmd spring-boot:run
```

启动后即可访问：

- Web 管理端：`http://127.0.0.1:8080`
- 接口前缀：`http://127.0.0.1:8080/api`

### 3. 浏览器预览 App 端（端口 5173）

```powershell
cd pandora-app
npm.cmd start
```

访问 `http://127.0.0.1:5173`，用演示账号登录。日常修改 `pandora-app/src/` 代码后刷新页面即可验证，无需打包。

### 4. 运行测试

```powershell
cd pandora-app
npm.cmd ci
npm.cmd test
npm.cmd run check
npm.cmd run test:ui  # 自动启动预览服务，运行全部 9 组模拟 API 浏览器检查
```

### 5. 打包安卓 APK

```powershell
cd pandora-app
npm.cmd run build:android -- --api-base http://10.0.2.2:8080/api --allow-http
```

构建脚本使用独立缓存的 Android 35 平台与构建工具，首次构建自动下载，无需安装 Android Studio 或 Gradle。

打包时用 `--api-base` 指定后端，不再修改 Java 源码或硬编码电脑 IP。上例仅用于模拟器；真机演示请填写电脑实际局域网地址，并保证同一网络。默认要求 HTTPS，只有显式 `--allow-http` 才允许本地 HTTP 演示。构建不会修改源清单或自动递增版本号。

正式签名必须使用 `--release --api-base https://实际域名/api --keystore 受保护密钥路径 --key-alias 发布别名 --version-code 新整数`，并在环境变量设置 `PANDORA_KEYSTORE_PASSWORD`（可另设 `PANDORA_KEY_PASSWORD`）。正式构建拒绝 HTTP 和默认演示签名；不带 `--release` 的包始终标记为演示包。仓库已有 APK 属于旧演示产物，使用修复版本需按实际服务器地址重新构建。

## 正式部署与升级

- 正式环境不启用 `demo` profile。注入独立的 `PANDORA_DB_URL`、`PANDORA_DB_USERNAME`、`PANDORA_DB_PASSWORD` 和 `PANDORA_JWT_SECRET`；默认不创建演示账号、不生成演示业务数据。曾提交过的数据库密码和 JWT 密钥应轮换，删掉源码中的值不能消除历史泄露。
- 首次空库部署可设置 `PANDORA_BOOTSTRAP_ENABLED=true`、`PANDORA_BOOTSTRAP_ADMIN_PHONE`、`PANDORA_BOOTSTRAP_ADMIN_PASSWORD`（12～64 位且不超过 72 字节）。仅空库创建管理员，已有数据库不会被覆盖；完成后移除这些初始化变量。管理员再从 Web 端创建公司成员，公开注册接口始终拒绝建号。
- 默认监听 `127.0.0.1:8080` 并要求 HTTPS。在同机反向代理配置有效 TLS 证书，将业务路径转发到该端口，覆盖客户端传入的 `Forwarded`/`X-Forwarded-*` 并写入可信协议、主机信息。不要将接受转发头的后端端口直接暴露公网。HTTPS 代理和证书需在实际环境配置。
- 用户只能补充姓名、性别、身份证格式资料；部门、手机号、角色和启用状态由管理员维护。填写资料不代表身份已经核验。旧的“待分配”账号无法登录；过去已自行填过部门的注册账号无法仅凭现有字段可靠识别，需要管理员核对成员名单并停用非公司账号。
- 后端 JAR 包含 Web 管理端资源，可独立运行；数据库仍需单独备份及配置。并发审核和任务写入使用数据库行锁，部署时请保留事务支持。

真实前后端端到端检查使用独立 H2 数据库，不连接本地 MySQL，也不使用演示密码。安装浏览器依赖后，在根目录运行：

```powershell
cd pandora-app
npm.cmd ci
npx.cmd playwright install chromium
cd ..
$env:PANDORA_E2E='true'
.\server\mvnw.cmd -f server/pom.xml verify
```

Windows 默认使用 Edge；其他系统使用 Playwright Chromium。可用 `PANDORA_BROWSER_CHANNEL` 指定浏览器渠道。`verify` 覆盖后端、真实浏览器业务闭环、Android 来源与 CSP，并构建 JAR。CI 工作流位于 `.github/workflows/verify.yml`。

## 接口概览

所有业务接口位于 `/api` 下，除登录外均需 `Authorization: Bearer <token>`。

| 接口 | 说明 |
| --- | --- |
| `POST /api/auth/login`、`GET /api/auth/me` | 登录、当前用户 |
| `GET /api/workspace` | 工作区聚合数据（任务、成员、公告等） |
| `GET /api/calendar/metadata?year=2026` | 自动同步的年度假期、调休、节气与同步状态，只读 |
| `POST /api/tasks/requests` | 提交任务创建／编辑／删除申请 |
| `POST /api/tasks/requests/{id}/review` | 审核变更申请 |
| `POST /api/tasks/{id}/progress` | 记录任务文字进展 |
| `POST /api/tasks/{id}/complete` | 标记任务完成（免审核） |
| `POST /api/tasks/{id}/pin` | 置顶／取消置顶任务 |
| `POST /api/logs`、`GET /api/logs/history` | 保存最近三天的日志、查询历史日志 |
| `GET /api/announcements` | 公告列表 |
| `GET/POST /api/admin/users` | 账号查询与创建 |
| `GET /api/admin/tasks`、`/admin/requests`、`/admin/logs`、`/admin/stats` | 管理端查询与统计 |
| `POST/DELETE /api/admin/announcements` | 公告维护 |
| `GET/POST /api/admin/highlights`、`PUT/DELETE /api/admin/highlights/{id}` | 十大内容查询、录入、编辑、发布与删除 |

数据库共 17 张表：`users`、`tasks`、`task_owners`、`task_history`、`change_requests`、`work_logs`、`log_versions`、`announcements`、`pins`、`highlights`、`tags`、`log_comments`、`daily_todos`、`demo_activity_days`、`operation_logs`、`workspace_notifications`、`calendar_years`，定义见 `server/src/main/resources/schema.sql`。

### 日历自动更新

- 日期和“今天”跟随设备本地时间，跨零点自动刷新；从后台恢复、重新联网或修改系统时间后也会检查。用户主动查看的其他日期保留，正在编辑的任务、事项与日志草稿不会改写日期。
- 农历由浏览器中文历法计算；24 节气由服务端 `lunar-java 1.7.8` 按北京时间计算，支持 1900～2100 年，不需每年更新日期表。
- 放假与调休无法仅靠日期算法推算。服务端启动后异步检查当年、次年，此后每 6 小时检查；浏览其他年份时也自动检查。使用 [holiday-cn](https://github.com/NateScarlet/holiday-cn) 提供的结构化数据及其中的政府公告来源。该项目是第三方整理源，并非政府实时接口；公告发布、数据源收录和下一次检查之间存在延迟。
- 自动同步验证年份、有效日期、重复日期、休班类型和 HTTPS 政府公告链接。主地址不可用时自动尝试同一仓库的 jsDelivr 分发地址；全部失败、404 或响应无效时保留最近有效数据，不把未知安排当作已公布。数据库 `calendar_years` 和 App 本地缓存支持后续断网使用；首次启动预置已核实的 [2025 年公告](https://www.gov.cn/zhengce/zhengceku/202411/content_6986383.htm)及 [2026 年公告](https://www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm)作为备用。新年度首次获取数据需服务端能访问 `raw.githubusercontent.com:443` 或 `fastly.jsdelivr.net:443`；分发缓存也可能产生更新延迟。
- 无日历人工编辑页面或写入 API。重启更新后的后端会自动创建缓存表；Android 已安装的旧包需重新构建安装后才包含本次跨日刷新和自动加载逻辑。

## 当前边界

- 一期按甲方核心诉求交付任务—审核—日志闭环，未接入 AI 功能。
- 任务变更支持指定单人审核或多人全员通过；选择菜单按组织分层展示，会签不设固定先后顺序。
- 演示口令只用于显式演示环境；正式环境的初始管理员、密码和签名密钥由外部配置。
- 安卓包为演示签名，正式发布需替换为受保护的发布签名。
- 后端默认本机 MySQL（localhost:3306），多环境连接由环境变量配置。

## Web 管理后台升级

管理端支持成员维护、公告编辑与置顶，以及公司重要事项、公司派发任务、个人重要事项的录入维护。任务申请在 App 任务页提交，审核在首页消息中处理。具体权限、数据库升级及验收方式见 [Web 管理端说明](web-admin/README.md)。
